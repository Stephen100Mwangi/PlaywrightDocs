# Setting up CI

Playwright tests can run on any CI provider

1. Setting up GitHub actions
When we run the command `npx init playwright@latest`, we have an option to add GitHub actions. When okayed, this command creates a `playwright.yml` file inside `.github/workflows` folder
This allows tests to run on each push & pull into main/master branch


    * npm i Vs npm ci
    `npm ci` is short for clean install. It installs dependencies exactly as specified in the *package-lock.json* without modifying any dependency files.
    1. Requires an existing *package-lock.json* or *npm-shrinkwrap.json*.
    2. Fails if versions in *package.json* and *package-lock.json* don’t match.
    3. Removes any existing node_modules before installing.
    4. Never modifies *package.json* or *package-lock.json*.
    5. Cannot install individual packages — installs the entire project at once.
    6. Faster than *npm install* in clean environments because it skips dependency resolution.

5. HTML report
    - Download the HTML report

    - Viewing the HTML report
    Once downloaded, extract the zip file preferably to a folder that has Playwright installed.
    Run the command, `npx playwright show-report "extractedFolder"` to view it on a browser

Once you run `npx playwright show-report`, click on the trace icon next to the test's file name as seen in the image above to try to find out why the tests are failing.

7. Publishing Report on Web
Downloading the HTML report as a zip file is not very convenient. We can utilize Azure Storage's static websites hosting capabilities to serve HTML reports on the Internet.

    - Create an Azure Storage account.
    - Enable Static website hosting for the storage account.
    - Create a Service Principal in Azure and grant it access to Azure Blob storage. Upon successful execution, the command will display the credentials which will be used in the next step.

```az ad sp create-for-rbac --name "github-actions" --role "Storage Blob Data Contributor" --scopes /subscriptions/<SUBSCRIPTION_ID>/resourceGroups/<RESOURCE_GROUP_NAME>/providers/Microsoft.Storage/storageAccounts/<STORAGE_ACCOUNT_NAME>```

    - Use the credentials from the previous step to set up encrypted secrets in your GitHub repository.
    - Go to your repository's settings, under GitHub Actions secrets, and add the following secrets:

- AZCOPY_SPA_APPLICATION_ID
- AZCOPY_SPA_CLIENT_SECRET
- AZCOPY_TENANT_ID

    Add a step that uploads the HTML report to Azure Storage.

This step will not work for pull requests created from a forked repository because such workflow doesn't have access to the secrets.
